# AI 口播影片工作流｜完整手冊

**把一段「有人對著鏡頭講話」的長錄影，變成一批可直接發布的短影音與長片。**

課程講座、商品開箱、產品介紹、自錄口播、直播回放、客戶見證都適用。

這份文件是「可匯入」的：把它整份貼給你的 AI（Claude、Codex、ChatGPT 皆可），
再照著〈第 0 章〉的啟動指令說一句話，AI 就知道整套流程、規則、參數與驗收標準。

搭配檔案：`engine/`（實際的渲染引擎，Python + ffmpeg，Windows／macOS 皆可跑）

---

## 第 0 章　怎麼把這份文件交給 AI

### 0-1　★ AI 讀到這裡，先做環境判別，不要急著動手

**這一節是給 AI 看的，不是給人看的。** 任何 AI 讀到這份手冊，第一件事是把下面四題問清楚
（能自己偵測的就自己偵測，偵測不到才問人）。**四題沒答完之前，不要開始剪任何東西。**

#### 第 1 題：我在什麼環境裡？（AI 自己判斷，不要問人）

| 我看到的情況 | 我是 | 我能做什麼 |
|---|---|---|
| 我有 Bash / Shell / 終端機工具，能讀寫本機檔案 | Claude Code、Codex CLI、Claude 桌面版 Cowork（在本機執行時） | **全部**：轉逐字稿、算圖、驗收 |
| 我只能在對話裡回字、不能執行指令、不能讀使用者硬碟 | ChatGPT 網頁版、Claude 網頁版、手機 App | **只能想**：盤點、選段、寫字幕、產設定檔內容 |
| 我能跑 Python 但沒有 ffmpeg，檔案還會定期清空 | ChatGPT 進階資料分析（Code Interpreter） | 半套，**不要用來算圖** |

自我檢測方法：試著執行 `ffmpeg -version`。
成功＝你是第一種；工具不存在或被拒絕＝你是第二／三種。

> **判成第二／三種時，最重要的一件事：老實說。**
> 直接告訴使用者「我沒辦法在這裡幫你算出 mp4，我可以幫你做到設定檔為止，
> 算圖那一步要你在自己電腦上跑」。**不要假裝在渲染，不要編造進度。**

#### 第 2 題：使用者的作業系統是 Windows 還是 macOS？

先自己偵測，偵測不到再問：

```bash
python -c "import platform; print(platform.system())"   # Windows / Darwin(=macOS) / Linux
```

差在哪：路徑寫法、ffmpeg 安裝方式、skill 放的資料夾、有沒有 CUDA。
細節見〈第 2 章〉與〈第 13 章〉。

#### 第 3 題：使用者用的是哪一個 AI 工具？

Claude 和 Codex **在剪片這件事上沒有能力差異**——兩邊都能讀檔、跑 ffmpeg、寫設定檔。
差別只有三個，都是「東西放哪」的問題：

| | Claude Code | Claude 桌面版 Cowork | Codex CLI |
|---|---|---|---|
| skill 放哪 | `~/.claude/skills/` | **從桌面版側邊欄的 Customize 啟用**（帳號層級，不吃本機資料夾） | `~/.agents/skills/` |
| 專案指示檔 | `CLAUDE.md` | 無 | `AGENTS.md` |
| 有沒有大小限制 | 無明顯限制 | 無明顯限制 | **AGENTS.md 合計上限約 32 KiB** |

> ⚠️ **Codex 使用者特別注意：不要把這份手冊整份貼進 `AGENTS.md`。**
> 手冊本身就超過 30 KB，會直接吃掉 Codex 的指示檔額度。
> 正確做法是 `AGENTS.md` 只放那份簡短的規則摘要（本包已附），
> 手冊當成**一般檔案**放在專案裡，讓 Codex 需要時自己去讀。

#### 第 4 題：使用者的錄影是哪一種？

模式一 雙畫面（課程／講座）還是模式二 單機位自錄（商品／產品／口播）？
判斷不出來就直接問，或請使用者給一張畫面截圖。**猜錯的成本是整批重做。**
對照表見〈0-4〉。

#### 判別完，照這張表決定接下來做什麼

| 環境 | 作業系統 | 接下來 |
|---|---|---|
| 能執行指令 | Windows | 檢查 `python` / `ffmpeg`（要含 libass）→ 填 `paths.py` → 從步驟①開始 |
| 能執行指令 | macOS | 同上，缺的用 `brew install python ffmpeg` → 從步驟①開始 |
| 只能對話 | 任何 | 說明限制 → 請使用者貼逐字稿 → 只做盤點／選段／字幕／設定檔內容 → 請他自己跑 |

### 0-2　貼給 AI 的第一段話（直接複製）

```
我要用一套既有的工作流，把錄影剪成短影音與長片。
我已經把完整手冊貼在下面／附上，請你先讀完，然後照這個流程幫我做。

開始之前，請先照手冊第 0-1 節做環境判別，把四題答完再動手：
你是哪種環境、我的作業系統、我用的 AI 工具、我的錄影是哪一種模式。
判別結果請先講給我聽。

規則：
1. 所有剪輯參數（靜音門檻、字幕長度、動畫時間）一律照手冊，不要自己發明。
2. 字幕分句由你手寫，不要用程式自動斷句。
3. 每次算圖前一定先跑 precheck.py，NG 就停下來修，不要硬跑。
4. 交付前一定跑 verify_long.py、monoaudit.py、cardchk.py 三個檢查。
5. 內容安全清單（第 8 章；商品片再加第 12-6 節）逐條檢查，有疑慮就先問我。
6. 你如果不能在這裡執行 ffmpeg，直接說，不要假裝在算圖。

我的專案資料夾是：（填路徑）
```

> 如果是模式二（商品／產品片），請 AI 一定要讀〈第 12 章〉——模式二的選段方法
> 與廣告用語檢查都在那裡，只讀前十一章會做出一支「剪得很乾淨但會被檢舉」的片子。

### 0-3　這套流程做得出什麼

| 產出 | 長度 | 用途 |
|---|---|---|
| 60 秒短影音 | 0:50–1:00 | Reels / Shorts / TikTok，負責被陌生人看到 |
| 中長片 | 1:30–4:00 | FB 動態、YouTube、私訊回覆，負責被相信 |
| 漲粉長片 | 2:30–3:00 | 同上，但片尾是「追蹤」不是賣課 |

每一支都自帶：片頭圖卡、逐句中文字幕、資訊動畫、BGM、片尾 CTA、品牌浮水印，
直式 9:16 與橫式 16:9 各一份。

### 0-4　兩種模式，先對號入座

| | **模式一　雙畫面錄影** | **模式二　單機位自錄** |
|---|---|---|
| 典型來源 | 課程、講座、線上會議側錄 | 商品開箱、產品介紹、口播、客戶見證 |
| 畫面 | 左投影片＋右講師鏡頭 | 一顆鏡頭拍到底（手機直拍或相機） |
| 長度 | 60–180 分鐘 | 3–30 分鐘 |
| 要量畫面幾何？ | **要**，每一場都要重量 | **不用**，直接跳過第 3 章② |
| `paths.py` 的 `CAM`/`SLIDE` | 填量到的 crop | 都填 `"null"` |
| 可用版面 | `A` / `B` / `C` | `F` / `P` |
| 內容盤點方式 | 概念區塊 A/B/C 分級 | 賣點盤點 ＋ 結構模板 |
| 最容易出事的地方 | 客戶資料、學員姓名、立場衝突 | 誇大不實、療效用語、業配沒揭露 |

**兩種模式共用同一套引擎、同一套剪輯參數、同一套設定檔格式。**
差別只在三處：畫面版面、內容盤點方法、內容安全清單。

第 1–11 章的規則兩種模式都適用（範例多半以課程片示範）。

## 第 1 章　三種 AI 怎麼分工（能做什麼／不能做什麼）

這是整份文件最重要的一章。**選錯工具會做不出來，不是你不會用。**

### 1-1　一句話結論

| 工具 | 能不能跑完整套 | 卡在哪 |
|---|---|---|
| **Claude Code / Claude Cowork（桌面版）** | ✅ 可以，全自動 | 無 |
| **Codex CLI（本機終端機）** | ✅ 可以，全自動 | 無 |
| **ChatGPT 網頁版 / Claude 網頁版** | ❌ 不行 | 不能執行本機 ffmpeg、不能讀你硬碟上的 4GB 錄影 |
| **ChatGPT Code Interpreter（進階資料分析）** | ⚠️ 半套 | 可跑 Python，但沒有 ffmpeg、檔案上限小、每次 session 重置 |

### 1-2　為什麼網頁版不行

這套流程的核心是**在你自己的電腦上跑 ffmpeg**：

- 一場錄影 1.5–4 GB，網頁版上傳不了，也不該上傳（裡面有客戶資料）
- 靜音偵測要對整段音軌掃描，需要真實的 ffmpeg
- 一支 60 秒短片要跑 20–30 次 ffmpeg，網頁版沒有這個能力
- 字型渲染（libass）要讀本機字型檔

**網頁版能做的**：內容盤點、選段、寫字幕文案、寫貼文、討論結構。
**網頁版不能做的**：轉逐字稿、算圖、任何產生 mp4 的動作。

### 1-3　三種能跑的工具，實際差在哪

| | Claude Code / Cowork | Codex CLI | ChatGPT 桌面版 + 手動 |
|---|---|---|---|
| 讀你的錄影檔 | ✅ | ✅ | ❌ 要你自己貼路徑 |
| 直接跑 ffmpeg | ✅ | ✅ | ❌ 你自己複製指令去終端機跑 |
| 寫／改設定檔 | ✅ | ✅ | ✅ 但要你自己存檔 |
| 看渲染 log 自己除錯 | ✅ | ✅ | ❌ 你要把錯誤訊息貼回去 |
| 一次排隊跑 7 支 | ✅ | ✅ | ❌ |
| 適合的人 | 不想碰終端機 | 習慣終端機 | 只想要 AI 幫你想內容 |

**建議**：
- 你要「說一句話就交片」→ Claude Code 或 Cowork
- 你自己會寫 code、想改引擎 → Codex CLI
- 你只想要 AI 幫你選段落、寫字幕稿，剪接自己來 → ChatGPT 網頁版 + 手動跑 `engine/`

### 1-4　混用是最省錢的做法

實務上最有效率的組合：

1. **ChatGPT / Claude 網頁版**：讀逐字稿、盤點內容、選段落、寫字幕分句與貼文
   （這步吃的是「想」的能力，不吃執行力，用便宜的介面就好）
2. **Claude Code / Codex**：把上一步的結果寫成設定檔、跑 precheck、算圖、驗收
   （這步吃的是執行力）

### 1-5　絕對不要做的事

- ❌ 把整支錄影上傳到任何雲端 AI（客戶資料、後台畫面、學員姓名）
- ❌ 讓 AI「自動斷句」產生字幕（見第 5 章，這是我們踩過最大的坑）
- ❌ 跳過 precheck 直接算圖（一支 3 分鐘，錯了就是白燒 3 分鐘）
- ❌ 用 AI 生成的「假數據」補進影片（所有數字都必須來自逐字稿）

## 第 2 章　環境準備（Windows / macOS 對照）

### 2-1　必裝

| 項目 | Windows | macOS |
|---|---|---|
| Python 3.10+ | 官網安裝，勾 Add to PATH | `brew install python` |
| ffmpeg（要含 libass） | Gyan full build，解壓後把 `bin` 加入 PATH | `brew install ffmpeg` |
| 逐字稿引擎 | `pip install faster-whisper` | 同左 |
| 繁化 | `pip install opencc-python-reimplemented` | 同左 |
| 影像處理 | `pip install pillow numpy` | 同左 |

驗證 ffmpeg 有 libass：

```
ffmpeg -filters | findstr subtitles      # Windows
ffmpeg -filters | grep subtitles         # macOS
```

沒看到 `subtitles` 就是版本不對，換 full build。

### 2-2　字型

用任何一套有 Bold 與 Heavy 兩個字重的中文字型都可以，我們用的是
**GenSenRounded2 TW**（思源柔黑，SIL Open Font License，可商用）。

放進 `_fonts/`，然後在 `engine/paths.py` 填檔名。

> ⚠️ **ASS 字幕的 `Fontname` 必須填「字型完整名稱」，不是家族名稱。**
> 例如家族是 `GenSenRounded2 TW`，但六個字重共用這個家族名，
> 你要填的是 `GenSenRounded2 TW B`。
> 驗證方法：`ffmpeg -loglevel verbose ...` 看輸出的 `fontselect:` 那一行選到哪支字型。
> 這一條錯了，字幕會默默變成別的字重，畫面看起來「怪怪的」但你找不出原因。

### 2-3　GPU（可選）

有 NVIDIA 顯卡的話，faster-whisper 用 CUDA 大約是即時的 7 倍速
（2 小時錄影約 16 分鐘轉完）。沒有 GPU 就用 CPU，慢但能跑。

macOS 沒有 CUDA，用 `device="cpu", compute_type="int8"`，
M 系列晶片跑 large-v3 大約是即時的 1–1.5 倍速。

## 第 3 章　九個步驟（整套流程）

```
①轉逐字稿 → ②量畫面幾何 → ③內容盤點 → ④選段 → ⑤寫設定檔
   → ⑥precheck → ⑦算圖 → ⑧驗收 → ⑨命名交付
```

### ① 轉逐字稿

```
python ingest.py "<專案資料夾>"
```

參數（已寫在 `ingest.py`，不要亂改）：

```python
model = "large-v3"
word_timestamps = True       # 必須，字幕時間點靠這個
vad_filter = True            # 過濾靜音，減少幻聽
beam_size = 5
condition_on_previous_text = False   # 關掉，避免整段跑掉
initial_prompt = "以下是繁體中文的行銷課程錄影逐字稿。"
```

輸出：`逐字稿/xx.json`（含每段 start/end）＋ `xx_compact.txt`（給人／AI 讀的精簡稿）

### ② 量畫面幾何

> **模式二（單機位自錄）跳過這一步。** 在 `paths.py` 把 `CAM` 與 `SLIDE` 都設成 `"null"`
> （ffmpeg 的 null filter＝原封不動通過），版面用 `F` / `P`，直接進入步驟③。

課程錄影通常是「左邊投影片＋右邊講師鏡頭」。你要量出三組數字：

- 分隔線的 x 座標
- 講師鏡頭的 crop（寬:高:x:y）
- 投影片區的 crop

用一段小程式抓三個時間點的畫格，掃描出深色的垂直分隔線與各區的內容邊界，
填進 `paths.py` 的 `CAM` 與 `SLIDE`。

> ⚠️ **每一場錄影都要重量一次。** 我們曾經以為某場的幾何不一樣而放棄一整段素材，
> 重量之後發現其實一樣——只是第一次量錯了。花 30 秒量，不要用猜的。

### ③ 內容盤點

把 `_compact.txt` 丟給 AI，請它照「講者實際講完一件事的邊界」切成概念區塊，
逐塊評級：

| 等級 | 定義 |
|---|---|
| **A** | 前提、推導、例子、可執行結論都有，拿掉前後文也聽得懂 |
| **B** | 主體完整但缺例子或缺結論，要補串場才成立 |
| **C** | 片段、閒聊、行政宣布、回答個別學員 |

同時要列出**避雷清單**（第 8 章）。

### ④ 選段

- **一個完整概念，講者習慣講 3 分鐘左右**（實測中位數 3.15 分）
- 教學片壓縮率 25–35%，不能再狠
- 60 秒短版 = 一個結論 + 一個數字，不解釋 why
- 2–3 分鐘 = 前提 → 推導 → 一個例子 → 可執行結論

把選中的段落逐字稿倒成 `選段/xxx.txt`（含精確到 0.01 秒的時間戳），這是下一步的原料。

### ⑤ 寫設定檔

見第 6 章。**這一步是人／AI 花最多時間的地方，也是品質的分水嶺。**

### ⑥ precheck

```
python precheck.py p3 p5 k02
```

會擋下：來源代號沒註冊、來源檔不存在、版面代號不存在、
字幕超出片長、字幕重疊、動畫超出片長、動畫重疊、動畫元件不存在、動畫缺必填參數。

**NG 就停，不要硬跑。**

### ⑦ 算圖

```
python queue.py p3 p5 k02
```

一支 60 秒約 2–3 分鐘，一支 2.5 分鐘長片約 5–9 分鐘。

### ⑧ 驗收（三支都要跑）

```
python verify_long.py p3 p5 k02      # 尺寸、時長、音畫 drift、內容段長靜音
python monoaudit.py                  # 段落順序有沒有往回跳
python cardchk.py                    # 片頭圖卡文字有沒有溢框
```

通過標準：

- 尺寸 1080×1920 / 1920×1080
- drift ≤ 0.05 秒
- 內容段長靜音 = 0
- 片頭圖卡最右白字 ≤ 畫面寬 − 60px

### ⑨ 命名交付

```
編號_主題_長度_尺寸.mp4
例：13_排程刊登與旺季加碼_60秒_直式_9x16.mp4
```

同時更新 `_成品/00_影片清單.md`，把「這支為什麼這樣剪、剪掉了什麼」寫進去。
**這份清單是整套流程能長期跑下去的關鍵**——三個月後你不會記得為什麼某段沒用。

## 第 4 章　剪輯規則（這些數字不要改）

| # | 規則 | 參數 |
|---|---|---|
| 1 | **零長靜音** | 超過 **0.80 秒**的死空氣一律剪掉 |
| 2 | 剪點留白 | 前緣留 **0.33 秒**、後緣留 **0.12 秒**，不要切到呼吸 |
| 3 | 靜音判定門檻 | **−38 dB** |
| 4 | 教學片氣口 | 留 **0.80 秒**。教學片套「零氣口」參數會喘不過氣，知識點吸收不了 |
| 5 | **Punch-in 章節式換畫面** | 每 **10–20 秒**換一次版面，3 分鐘不換畫面會非常悶 |
| 6 | 破題圖卡 | **1.2–1.3 秒**（漲粉長片可到 2.2 秒） |
| 7 | 相鄰字卡 | 至少留 **0.06 秒**間隔 |
| 8 | **不切語尾** | 寧可多留 0.2 秒，不要把句尾切掉 |
| 9 | 逐字時間戳 | 字幕時間必須來自 word timestamps，不能估 |
| 10 | 人聲響度 | **−15 LUFS**，TP −1.5 |
| 11 | BGM 響度 | **−32 LUFS**，TP −9（比一般建議更小，因為是說話為主的內容） |
| 12 | BGM 強起 | 前 3 秒平均約 **−10 dB**，開頭要有存在感 |
| 13 | 音量固定 | 用 `amix` 固定比例，**不要用 sidechain 自動閃避**（教學片會忽大忽小） |
| 14 | 片尾淡出 | 1.2 秒 |

### 字幕規則

- 直式一行約 **13–16 字**（字級 58px）；放大版 72px 時約 12–13 字
- 每一秒被保留的畫面，**都要有字幕，或者被剪掉**
  （我們曾經有一支片有三段「他在說話但沒字幕」，就是漏了這條）
- 分句由人／AI 手寫，**不要程式自動斷句**

## 第 5 章　為什麼字幕一定要手寫

我們試過用程式自動斷句，結果是：

- 從詞中間斷開：`Me\Nta`、`直\N接貼上`
- 留下孤兒行：只有一個字的 `子`、`公斤`、`麼`
- 把不相干的兩句黏在一起

**結論：程式只做兩件事——簡轉繁（OpenCC `s2twp`）＋專有名詞校正表。
斷句與潤飾一律人工（或由 AI 逐句寫，人審）。**

專有名詞校正表要自己維護，例如：

| 語音辨識出來 | 正確 |
|---|---|
| 高效素成廣告 | 高效速成廣告（Advantage+） |
| 貨客迴圈 | 顧客迴圈 |
| 淡忘記 | 淡旺季 |
| ShareGPT | ChatGPT |
| 父親解 | 父親節 |
| 後輩子 | 棉被 |

## 第 6 章　設定檔規格

一支影片 = 一個 `xxx_cfg.py`。

```python
# -*- coding: utf-8 -*-
"""p3 七八成預算給轉換｜60 秒版"""
from anim_lib import TEAL, GREY, GOLD

INTRO_D, CTA_D = 1.3, 7.0          # 片頭圖卡秒數、片尾 CTA 秒數
SUB_SCALE = 1.0                    # 字幕放大倍率（漲粉長片用 1.25）
BRAND = "你的品牌"                  # 右下角浮水印
LAYOUTS = ["A", "B"]               # 版面序列，見下

CTA = ("想知道整套怎麼做嗎？\\N（第二行）"
       "\\N\\N（第三行）")

TITLE = ("第一行標題", "第二行副標")   # 片頭圖卡
TOPIC = "系列名稱"                    # 畫面上方的小標

SPANS = [                          # ★ 要保留的原始片段（來源代號, 起, 迄）
 ("a1", 4463.04, 4470.12),
 ("a1", 4474.86, 4490.28),
]

LINES = [                          # ★ 字幕（body 時間軸，非原始時間軸）
 (0.00,  4.62, "投廣告要投曝光還是流量"),
 (4.62,  7.08, "我們投廣告\\N都直接投轉換廣告"),
]

CARDS = [                          # 學員發言改成黃色字卡（可留空）
 (0.20, 6.20, "〔學員提問〕⋯"),
]

ANIM = [                           # 資訊動畫（起, 長度, 元件, 參數）
 (7.5, 14.0, "checklist", dict(title="投放順序", items=["第一波：直接投轉換", "成效掉了才補漏斗"])),
]
```

### 三個時間軸，一定要搞清楚

| 時間軸 | 誰用 | 說明 |
|---|---|---|
| **原始時間軸** | `SPANS` | 錄影檔上的秒數 |
| **body 時間軸（未剪靜音）** | `LINES` `CARDS` `ANIM` | 把 SPANS 依序接起來後的秒數 |
| **成品時間軸** | 程式自己算 | 剪掉靜音後的秒數 |

**`LINES` / `ANIM` 一律寫 body 時間軸，程式會自動換算到成品時間軸。**

> ⚠️ **改了 SPANS 就一定要同步位移 LINES。**
> 我們曾經在 SPANS 中間插了一刀卻忘了位移，結果 14 秒之後的字幕整整差 3.83 秒。

### 版面

| 代號 | 內容 | 什麼時候用 |
|---|---|---|
| A | 講師上、投影片下 | 一般 |
| B | 投影片放大、講師縮右上 | 一般（與 A 交替） |
| **C** | **只放講師 + 模糊背景** | **投影片是空白／靜止／有客戶資料時** |
| **F** | **全幅（模式二）** | 單機位自錄，講話、看鏡頭的段落 |
| **P** | **punch-in 特寫（模式二）＝ `F` 再放大 1.18 倍** | 單機位自錄，講細節、指產品、情緒段落 |

`LAYOUTS = ["A","B"]` 會每段交替；`LAYOUTS = ["C"]` 則全片只放講師；
模式二用 `LAYOUTS = ["F","P"]`。

> `F` 遇到來源比例與輸出比例不同時會 letterbox 到模糊底；`P` 是在 `F` 的基礎上
> 放大 1.18 倍，**不是死板的中央裁切**，所以直拍、橫拍、19.5:9 手機比例都不會爆框。
> 橫拍素材出 9:16 時兩者都會留模糊邊，`P` 的畫面比較滿。
> 講話段落用 `F`（不會切到頭），產品特寫用 `P`。

> 什麼時候該用 C：
> 1. 那段在示範後台，畫面上有真實客戶名稱或數據
> 2. 那段投影片根本沒換（我們量過一支，螢幕 6 分鐘完全沒變，畫格差異只有 0.4–0.7）
> 用 C 之後，資訊改用動畫呈現，畫面反而更清楚，也不用逐幀打碼。

## 第 7 章　動畫元件（必填參數）

| 元件 | 用途 | 必填參數 |
|---|---|---|
| `checklist` | 條列打勾 | `title`, `items`（list） |
| `formula` | 計算式逐行揭露，最後一行金色 | `title`, `rows`（list of `(標籤, 值, 是否highlight)`） |
| `stamp` | 兩行重點蓋章 | `line1`（`line2` 可選） |
| `bars2` | 兩項長條對比 | `title`, `items`（`(值, 標籤, 值文字, 顏色)`） |
| `donut` | 圓環佔比 | `title` |
| `count` | 數字滾動 | `value` |
| `vs` | 左右對決 | `left`, `right` |

配色（`anim_lib.py`）：

```python
TEAL = (20, 200, 190)    # 主色
GOLD = (255, 214, 0)     # 強調／結論
DARK = (10, 20, 22)      # 底
GREY = (150, 150, 145)   # 次要
RED  = (226, 86, 74)     # 警示
```

**動畫節奏**：

| 模式 | 60 秒 | 2.5 分鐘 |
|---|---|---|
| 一（雙畫面） | 3–5 個 | 10–15 個（約每 12–15 秒一個） |
| 二（單機位） | **5–7 個** | **15–20 個**（約每 8–10 秒一個） |

模式二要放得比較密，因為單機位沒有第二顆鏡頭可以切，畫面變化幾乎全靠動畫扛。

## 第 8 章　內容安全檢查表

課程錄影是講給學員聽的，**不是講給網路上的陌生人聽的**。這張表逐條過：

| 類別 | 要找什麼 | 處理 |
|---|---|---|
| 真實客戶名 | 品牌名、產品名 | 剪掉或換段 |
| 後台畫面 | 帳號、客戶名稱、真實 ROAS／客單價 | 換版面 C，或逐幀打碼 |
| 學員姓名 | 講師 cue 學員、學員回答 | 只留講師，回答改成黃色字卡 |
| 自家報價 | 月費、抽成、接案門檻 | 一律不用 |
| 過期資訊 | 「下週上課」「這個密碼之後會拿掉」 | 剪掉 |
| 密碼／連結 | GPT 密碼、未公開社團連結 | 剪掉或消音 |
| 灰色手法 | 規避平台審查、重刷免費額度、買互動 | **一律不用** |
| 講者自己說「這個不用講出去」 | 直接關鍵字搜逐字稿 | 整段剪掉 |
| 第三方講師 | 「剛才 XXX 老師有講」 | 那段換人了，不要混進同一個系列 |
| 立場衝突 | 內容是講給 A 群人聽，但你要招的是 B 群人 | 重新選段，不是重新配字幕 |

> **最後一條最容易被忽略。**
> 我們的錄影是講給「代操投手」聽的，但要推的課程明文排除代理商。
> 所以「一個月八萬怎麼收費」「我們 8 月接手」「月報怎麼包裝給客戶」這些
> 講得很好的段落全部不能用——不是內容不好，是立場不對。

**做商品／產品片的人，這張表之外還要再過一張〈第 12 章〉的廣告用語表。**
自錄商品片最容易出事的不是隱私，是講過頭。

## 第 9 章　我們實際踩過的坑

| # | 症狀 | 真正的原因 | 修法 |
|---|---|---|---|
| 1 | **動畫全部擠在一起** | `remap()` 換算時間軸時只比對「來源檔名」，同一支錄影被非遞增取用（74 分 → 19 分 → 40 分）就會全部映射錯位。**字幕也會一起錯** | 改成用「段落索引」比對；用 `monoaudit.py` 找出會踩雷的設定 |
| 2 | 片頭文字超出畫面 | 圖卡字級寫死 | 改成自動縮字；`cardchk.py` 量實際輸出 |
| 3 | 字幕整段差 3.83 秒 | 改了 SPANS 沒同步位移 LINES | 任何 SPANS 變動都要同步位移 |
| 4 | 有人在說話但沒字幕 | 選段時漏寫 | 規則：每一秒保留畫面都要有字幕，否則剪掉 |
| 5 | 自動斷句字幕不能看 | 斷在詞中間、孤兒行 | 程式只做繁化＋術語校正，斷句人工 |
| 6 | 字幕字重不對 | ASS 的 `Fontname` 填了家族名不是完整名 | 用 `-loglevel verbose` 看 `fontselect:` |
| 7 | 動畫算到一半掛掉 | 元件缺必填參數（例如 `formula` 沒給 `title`） | precheck 加入必填參數檢查 |
| 8 | 段落用了不存在的來源代號 | 設定檢查只驗時間，沒驗來源 | precheck 加入來源存在性檢查 |
| 9 | 影片超過 60 秒 | 逐字稿本身沒有可剪的靜音，trim 砍不動 | 手動拿掉一句重複的話重算 |
| 10 | 投影片畫面完全沒換 | 講者在口述，沒操作 | 換版面 C + 補動畫 |

## 第 12 章　模式二：單機位自錄（商品／產品／口播）

前十一章的規則你都適用，這一章只講**不一樣的地方**。

### 12-1　設定：三行就切換完

`paths.py` 裡把畫面幾何換掉：

```python
SEPARATOR_X = 0
CAM   = "null"      # ffmpeg 的 null filter＝原封不動通過
SLIDE = "null"
```

設定檔裡版面改成：

```python
LAYOUTS = ["F", "P"]
```

沒了。其他一切照舊——去靜音參數、字幕規則、動畫元件、precheck、驗收全部一樣。
範例檔在 `configs_example/prod_cfg.py`。

### 12-2　最大的差別：沒有天然的段落邊界

課程錄影有一個很好用的特性：**講者會自己講完一個概念**，平均 3 分鐘左右，
你只要沿著他的思路切就好。

自錄影片沒有這個。一段 8 分鐘的開箱可能從頭到尾都在講同一罐東西，
沒有「這一段講完了」的訊號。所以模式二要靠**結構模板**反過來找段落。

60 秒版本，挑一個模板套：

| 模板 | 結構 | 適合 |
|---|---|---|
| **痛點→解法** | 痛點 → 為什麼一直沒解決 → 這個東西怎麼解 → 怎麼用 | 功能型商品 |
| **開箱** | 我為什麼買 → 拆開第一印象 → 兩個優點一個缺點 → 適合誰 | 實體選物 |
| **迷思破解** | 大家都以為 X → 其實是 Y → 證據 → 那該怎麼做 | 知識型帶貨 |
| **使用教學** | 常見錯誤 → 正確步驟 1-2-3 → 差別在哪 | 保養、工具、軟體 |
| **見證** | 之前的狀況 → 用了多久 → 具體改變 → 給誰的建議 | 客戶訪談 |

做法是：讀完逐字稿，**先決定要套哪個模板，再去逐字稿裡撿對應的句子**。
撿不齊就換模板，或換一支影片，不要用旁白硬補。

2–3 分鐘版本 = 60 秒版本 ＋ 使用情境 ＋ **一個缺點** ＋ 適合／不適合誰。

> **主動講缺點的片子留存率明顯比較好，也比較不會被檢舉誇大。**
> 剪的時候很容易把「但是它有點貴」「不適合乾肌」剪掉——不要剪，那是最有說服力的部分。

### 12-3　鉤子（前 3 秒）

短影音的生死線在前 3 秒。規則：

- **鉤子必須是他真的講過的話**。從逐字稿裡撿，不要另外補錄旁白，
  也不要用 AI 寫一句放在字幕上假裝他說的。
- 找不到好鉤子就換段。一整支影片裡通常只有 1–2 句真的能當鉤子。
- 能當鉤子的句子長這樣：一個反直覺的結論、一個具體數字、一個大家都有的痛點。
  形容詞開頭（「這個真的超好用」）一律不是鉤子。

### 12-4　一支只講一件事

開箱片最常見的失敗，是把五個賣點塞進 60 秒，結果觀眾一個都沒記住。

- 一支 60 秒 = **一個賣點 + 一個證據**。
- 五個賣點就切成五支，不要塞在一起。這樣素材利用率反而更高。
- 「要有一個具體的東西」：一個數字、一個對比、一個看得到的動作。
  整段都是形容詞的片段不要用。

### 12-5　沒有 demo 畫面怎麼辦

自錄片常常「講到某個功能但鏡頭沒拍到」。處理順序：

1. 用 `P` 版面 punch-in，讓畫面至少有變化
2. 補一個 `checklist` 或 `stamp` 動畫，把他講的內容視覺化
3. 真的講不清楚就剪掉這一段

**不要硬插無關的 B-roll。** 觀眾看得出來那不是同一個場景，
信任感掉得比畫面單調還快。

### 12-6　廣告用語檢查表（模式二專屬）

第 8 章那張表要過，這張也要過：

| 類別 | 要找什麼 | 處理 |
|---|---|---|
| **療效／醫療用語** | 治療、根治、消炎、抗菌、抗癌、瘦身、豐胸、生髮、降血糖、改善過敏 | 食品、保養品、一般商品**一律不能用**。改講使用感受 |
| **最高級用語** | 第一、最有效、唯一、絕對、100%、永久、保證 | 拿掉。真的有得獎或第三方數據就標明出處與時間 |
| **沒根據的數字** | 「有效率 90%」「三天見效」「回購率第一」 | 沒有可指名的來源就整句剪掉，不要改成模糊講法 |
| **絕對保證** | 保證瘦、無效退費 | 只留你真的做得到、也真的寫在條款裡的 |
| **比較性廣告** | 直接指名對手品牌說它爛 | 改成「市面上常見的做法」，不指名 |
| **業配／聯盟／贈品** | 廠商送的、有分潤連結、有稿費 | **一定要揭露**，字幕或畫面標「合作」「贈品」 |
| **他人素材** | 網路圖片、對手的影片、路人臉孔入鏡 | 沒授權就不要用 |
| **未上市／未取證** | 還沒拿到許可字號的產品 | 先不要拍 |
| **個資** | 收件地址、訂單截圖、客戶對話截圖 | 打碼或剪掉 |

> ⚠️ 這是實務避雷清單，**不是法律意見**。食品、化粧品、醫療器材、保健食品的宣稱，
> 各國規範不同而且會變，上架前請自行確認或找專業人士看過。
>
> 對 AI 的指示：**你判斷不了「這樣講到底可不可以」。有疑慮就標記起來問人，不要自己放行，
> 也不要為了讓句子通過就自己改寫成模糊講法**——模糊的誇大還是誇大。

### 12-7　CTA 怎麼寫

| 目的 | CTA 寫法 |
|---|---|
| 導購 | 「完整規格與售價在下方連結」——不要在片尾喊價，價格會變 |
| 漲粉 | 「每週一支開箱，只講我自己真的在用的」——講**你會持續給什麼**，不是「請追蹤我」 |
| 名單 | 「留言『尺寸』我把對照表私訊給你」——要一個低成本的動作 |

一支影片只放一個 CTA。三個都要就是三個都不會做。

### 12-8　給 AI 的 prompt（模式二）

```
這是一支自錄的商品介紹影片逐字稿（含時間戳）。請照工作流手冊第 12 章：

1. 先判斷這支適合哪一個結構模板，說明為什麼
2. 從逐字稿裡撿出前 3 秒的鉤子候選，列 3 句給我挑（必須是他真的講過的話）
3. 選出可剪成 50–55 秒的片段，列成 SPANS
4. 逐句手寫 LINES，直式一行不超過 16 字
5. 放 5–7 個動畫，照第 7 章的元件與必填參數
6. LAYOUTS 用 ["F","P"]
7. 過一次第 8 章與第 12-6 節的檢查表，把有疑慮的句子單獨列出來問我

不要幫商品補任何我沒講過的數字或功效。
```

## 第 13 章　安裝位置：哪個工具、哪個系統、東西放哪

這一章回答一個很實際的問題：**這包檔案下載下來之後，到底要放到哪裡，AI 才看得到？**

### 13-1　這包裡有什麼、各自要放哪

| 檔案 | 是什麼 | 放哪 |
|---|---|---|
| `SKILL.md` | 規則總表，AI 的「主檔」 | 依工具而定，見 13-2 |
| `references/手冊.md` | 完整手冊（就是你正在讀的這份） | 跟 `SKILL.md` 同一個資料夾底下的 `references/` |
| `AGENTS.md` | 給 Codex 的簡短指示 | **專案根目錄**（Claude 使用者可略過） |
| `scripts/` | 引擎本體，真正在跑 ffmpeg 的程式 | 專案裡任何位置都可以，慣例放 `videoedit/engine/` |
| `scripts/paths.py` | 環境設定 | 跟 `scripts/` 一起，**唯一要改的檔案** |
| `README.md` | 給人看的快速上手 | 隨便放，AI 不需要它 |

> **`SKILL.md` 是 Agent Skills 開放標準**（由 Anthropic 提出後開源），
> Claude Code、Codex CLI、Cursor、Gemini CLI、GitHub Copilot 等三十多種工具都支援。
> **同一份 `SKILL.md` 兩邊通用，不用改任何一個字**——差別只有「放哪個資料夾」。

### 13-2　skill 放哪（依工具 × 作業系統）

#### Claude Code（終端機版）

| | 路徑 | 範圍 |
|---|---|---|
| macOS 個人 | `~/.claude/skills/talking-head-video-cut/SKILL.md` | 所有專案 |
| Windows 個人 | `%USERPROFILE%\.claude\skills\talking-head-video-cut\SKILL.md` | 所有專案 |
| 專案 | `<專案>/.claude/skills/talking-head-video-cut/SKILL.md` | 只有這個專案 |

放好之後，Claude Code 會在需要時自動載入，也可以直接打 `/talking-head-video-cut` 叫它。
**不用重開**，Claude Code 會偵測資料夾變動。

#### Claude 桌面版（Cowork）

**這裡不一樣，要特別注意。** Cowork 工作階段**不讀你電腦上的 `~/.claude/skills/`**，
它載入的是**你 claude.ai 帳號上啟用的 skill**。

安裝方式：桌面版側邊欄的 **Customize** → 加入 skill；或到 claude.ai 的 skill 設定頁上傳。
本包附的 `.skill` 檔就是給這個用的——把它交給 Claude，它會問你要不要存起來。

> 也就是說：**在 Claude Code 裡放進 `~/.claude/skills/` 的 skill，Cowork 看不到。**
> 兩邊都要用的話，兩邊都要裝一次。

#### Codex CLI

| | 路徑 | 範圍 |
|---|---|---|
| macOS 個人 | `~/.agents/skills/talking-head-video-cut/SKILL.md` | 所有專案 |
| Windows 個人 | `%USERPROFILE%\.agents\skills\talking-head-video-cut\SKILL.md` | 所有專案 |
| 專案 | `<專案>/.agents/skills/talking-head-video-cut/SKILL.md` | 只有這個專案 |

Codex 會從目前的工作目錄往上一路掃到 repo 根目錄找 `.agents/skills`。

#### ChatGPT 網頁版 / Claude 網頁版 / 手機

**沒有 skill 機制。** 直接把 `SKILL.md` 與 `references/手冊.md` 的內容貼進對話，
或把檔案上傳當附件。然後照〈0-2〉的啟動指令說一句話。
記得：這條路線**做不出 mp4**，只能做到設定檔為止。

### 13-3　專案指示檔（`CLAUDE.md` / `AGENTS.md`）

skill 是「需要時才載入」，專案指示檔是「每次都載入」。兩者用途不同：

| 工具 | 檔名 | 位置 |
|---|---|---|
| Claude Code | `CLAUDE.md` | 專案根目錄 |
| Codex CLI | `AGENTS.md` | 專案根目錄（另有全域 `~/.codex/AGENTS.md`） |

Codex 會從專案根目錄往下走到你目前所在的目錄，把沿路的 `AGENTS.md` 串起來，
越靠近目前目錄的越優先。

> ⚠️ **Codex 的 `AGENTS.md` 合計有大小上限，預設約 32 KiB**
> （可用設定 `project_doc_max_bytes` 調整）。
> 這份手冊本身就 30 KB 以上，**整份貼進 `AGENTS.md` 會直接吃光額度、擠掉你其他的專案指示**。
>
> **正確做法**：`AGENTS.md` 只放本包附的那份簡短規則摘要（約 3 KB），
> 手冊放在專案裡當一般檔案，Codex 需要時會自己去讀。
> Claude Code 的 `CLAUDE.md` 沒有這麼緊的限制，但同樣建議只放摘要。

### 13-4　最省事的做法：整包丟進專案

如果你懶得管上面那些路徑，最簡單的做法是**整包解壓到專案根目錄**，然後跟 AI 說
「這個資料夾裡有 SKILL.md 和 references/手冊.md，請先讀完」。

skill 機制的好處只有一個：**不用每次都提醒 AI 去讀**。
一次性的專案，直接丟資料夾就夠了；要長期重複用，才值得裝成 skill。

### 13-5　常見狀況排除

| 症狀 | 原因 | 解法 |
|---|---|---|
| Claude Code 看不到 skill | 放到 `.claude/skill/`（少了 s）或少了一層資料夾 | 路徑必須是 `.claude/skills/<名字>/SKILL.md` |
| Cowork 看不到 skill | 裝在 `~/.claude/skills/`，但 Cowork 只讀帳號層級 | 從桌面版 Customize 重裝一次 |
| Codex 看不到 skill | 放到 `.claude/skills/` | Codex 找的是 `.agents/skills/` |
| Codex 忽略部分指示 | `AGENTS.md` 超過 32 KiB 被截斷 | 把長內容移出去當一般檔案 |
| skill 載入了但 AI 不照做 | `description` 沒對上使用者的講法 | 直接用 `/talking-head-video-cut` 叫它 |
| AI 說它在算圖但沒有檔案 | 它其實不能執行指令（網頁版） | 回到〈0-1〉重做環境判別 |

## 附錄　工時參考

| 項目 | 時間 |
|---|---|
| 2 小時錄影轉逐字稿（GPU） | 約 16 分鐘 |
| 內容盤點（AI 協助） | 20–30 分鐘 |
| 寫一支 60 秒的設定檔 | 15–25 分鐘（幾乎都在寫字幕分句） |
| 算一支 60 秒 | 2–3 分鐘 |
| 算一支 2.5 分鐘 | 5–9 分鐘 |
| **一支 60 秒短影音總計（模式一）** | **約 30 分鐘** |
| **一支 2–3 分鐘中長片總計（模式一）** | **約 1.5–2 小時** |
| 一支 60 秒商品片總計（模式二） | 約 20–25 分鐘（不用量幾何、字幕句數少，但動畫多） |
| 10 分鐘自錄影片轉逐字稿（GPU） | 約 1.5 分鐘 |

中長片工時大約是短影音的 6–8 倍，差在：字幕 60–90 句（短片 8–13 句）、
切點 20–40 刀（短片 2–4 刀）、每 10–20 秒要換一次畫面。

**排程時請用這個比例估，不要用「長度比」估。**
