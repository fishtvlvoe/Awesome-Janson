# 口播錄影 → 短影音／長片 工作流

一套在**使用者自己電腦上**執行的剪片流程：Python + ffmpeg，Windows 與 macOS 皆可跑。
輸入是一段長錄影，輸出是一批帶字幕、動畫、圖卡、BGM 的成品 mp4（直式 9:16 ＋ 橫式 16:9）。

**適用前提只有一個：畫面上有人在講話，而且講的內容本身有價值。**
是課程、是開箱、是產品介紹、是客戶訪談都可以。不適用於純畫面剪輯（風景、產品空景、
音樂 MV）——那種片子的節奏靠鏡頭不靠語意，這套流程幫不上忙。

## 開場：先做環境判別，四題答完才動手

**這一段不要跳過。** 能自己偵測的就自己偵測，偵測不到才問人。

### 1. 我能不能執行本機指令？

試著跑 `ffmpeg -version`。

- **成功** → 你是 Claude Code / Codex CLI / Cowork（本機執行），走完整流程。
- **失敗或沒有這個工具** → 你是網頁版對話，**只能做到設定檔為止**。
  這時最重要的一件事是老實說：「我沒辦法在這裡幫你算出 mp4，算圖那一步要你在自己電腦上跑。」
  **不要假裝在渲染，不要編造進度。**

### 2. 使用者的作業系統？

```bash
python -c "import platform; print(platform.system())"   # Windows / Darwin(=macOS) / Linux
```

影響：路徑寫法、ffmpeg 安裝方式、有沒有 CUDA。

### 3. 使用者用哪個 AI 工具？

Claude 和 Codex **在剪片這件事上沒有能力差異**，差別只在「檔案放哪」：

| | Claude Code | Claude 桌面版 Cowork | Codex CLI |
|---|---|---|---|
| skill 位置 | `~/.claude/skills/` | 帳號層級，從桌面版 **Customize** 啟用（**不讀本機資料夾**） | `~/.agents/skills/` |
| 專案指示檔 | `CLAUDE.md` | 無 | `AGENTS.md` |
| 限制 | — | — | **`AGENTS.md` 合計上限約 32 KiB** |

> ⚠️ Codex：**不要把 `references/手冊.md` 貼進 `AGENTS.md`**，它超過 30 KB，會吃光額度。
> `AGENTS.md` 只放本包附的簡短摘要，手冊留在專案裡讓 Codex 需要時自己讀。

完整安裝路徑對照（含 Windows 寫法與排錯表）見 `references/手冊.md` 第 13 章。

### 4. 錄影是哪一種模式？

見下一節。判斷不出來就直接問，或請使用者給一張畫面截圖。**猜錯的成本是整批重做。**

### 然後檢查環境有沒有裝齊

`python`、`ffmpeg`（需含 libass）、`faster-whisper`、`opencc-python-reimplemented`、
`pillow`、`numpy`。缺什麼先講，不要跑到一半才炸。

最後確認 **`scripts/paths.py` 有沒有填**——專案路徑、字型、BGM、來源錄影代號、
以及依模式二選一的畫面幾何。沒填就先問使用者。

## 兩種模式（第 4 題的對照表）

| | **模式一　雙畫面錄影** | **模式二　單機位自錄** |
|---|---|---|
| 典型來源 | 課程、講座、線上會議側錄、研討會 | 商品開箱、產品介紹、口播、客戶見證、Podcast 錄影 |
| 畫面 | 左投影片＋右講師鏡頭 | 一顆鏡頭拍到底（手機直拍或相機） |
| 長度 | 60–180 分鐘 | 3–30 分鐘 |
| 要量畫面幾何？ | **要**，每一場都要重量 | **不用** |
| `paths.py` 的 `CAM`/`SLIDE` | 填量到的 crop | 都填 `"null"` |
| 可用版面 | `A` / `B` / `C` | `F` / `P` |
| 內容盤點方式 | 概念區塊 A/B/C 分級 | 賣點盤點 + 結構模板 |
| 最需要小心的 | 客戶資料、學員姓名、立場衝突 | 誇大不實、療效用語、業配揭露 |

**兩種模式共用同一套引擎、同一套剪輯參數、同一套設定檔格式。**
差別只在畫面版面、內容盤點方法、與內容安全清單這三處。

## 九個步驟

```
①轉逐字稿 → ②量畫面幾何 → ③內容盤點 → ④選段 → ⑤寫設定檔
   → ⑥precheck → ⑦算圖 → ⑧驗收 → ⑨命名交付
```

```bash
python ingest.py "<專案資料夾>"     # ①
python precheck.py p3 p5 k02         # ⑥ NG 就停，不要硬跑
python queue.py   p3 p5 k02          # ⑦
python verify_long.py p3 p5 k02      # ⑧
python monoaudit.py                  # ⑧ 段落順序
python cardchk.py                    # ⑧ 片頭圖卡溢框
```

**模式二可以直接跳過步驟②**（`CAM = SLIDE = "null"`）。
其餘八步兩種模式完全一樣。細節見 `references/手冊.md` 第 3 章。

## 不可協商的規則（兩種模式都一樣）

這些數字是實測出來的，**不要自己發明或「優化」**：

| 規則 | 值 |
|---|---|
| 靜音超過此長度就剪 | 0.80 秒 |
| 剪點前緣／後緣留白 | 0.33 秒／0.12 秒 |
| 靜音判定門檻 | −38 dB |
| 換版面頻率 | 每 10–20 秒 |
| 片頭圖卡 | 1.2–1.3 秒（漲粉長片 2.2 秒） |
| 相鄰字卡最小間隔 | 0.06 秒 |
| 人聲響度 / BGM 響度 | −15 LUFS / −32 LUFS（TP −9） |
| 直式字幕一行 | 13–16 字（58px）；放大版 12–13 字（72px） |

外加四條硬規定：

- **不切語尾**——寧可多留 0.2 秒。
- **每一秒被保留的畫面都要有字幕**，否則就該剪掉。
- **字幕分句一律手寫**（AI 逐句寫、人審）。程式只做簡轉繁（OpenCC `s2twp`）＋術語校正表。
  自動斷句會斷在詞中間、留下單字孤兒行——這是踩過最大的坑。
- **所有數字都必須來自逐字稿或使用者提供的事實**，不准生成假數據補進影片。
  模式二特別容易犯：AI 很想幫商品補一個「效率提升 30%」，**不行**。

## 設定檔：三個時間軸

一支影片 = 一個 `xxx_cfg.py`。完整欄位規格見 `references/手冊.md` 第 6 章，
範例在 `scripts/configs_example/`（`p3_cfg.py` 是課程片、`prod_cfg.py` 是商品片、
`L1_cfg.py` 是多段串接的長片）。

| 時間軸 | 誰用 |
|---|---|
| 原始時間軸（錄影檔秒數） | `SPANS` |
| body 時間軸（SPANS 接起來、**未剪靜音**） | `LINES` `CARDS` `ANIM` |
| 成品時間軸 | 程式自己算，不要手寫 |

> **改了 `SPANS` 就必須同步位移 `LINES` / `CARDS` / `ANIM`。** 漏了這步，
> 後面整段字幕會固定偏移好幾秒，而且畫面看起來「只是有點怪」，很難察覺。

### 版面代號

**模式一（雙畫面）**

| 代號 | 內容 | 什麼時候用 |
|---|---|---|
| `A` | 講師上、投影片下 | 一般 |
| `B` | 投影片放大、講師縮右上 | 一般（與 A 交替） |
| `C` | 只放講師 ＋ 模糊背景 | 投影片空白、靜止、或有客戶資料時 |

**模式二（單機位）**

| 代號 | 內容 | 什麼時候用 |
|---|---|---|
| `F` | 全幅。來源不是目標比例時自動 letterbox 到模糊底 | 講話、講重點、看鏡頭 |
| `P` | punch-in 特寫＝`F` 再放大 1.18 倍 | 講細節、指產品、情緒段落 |

`LAYOUTS = ["F", "P"]` 會每段交替。**單機位沒有第二顆鏡頭，換畫面就只能靠這個交替
＋動畫**——所以模式二的動畫要放得比模式一密一點，不然 60 秒會很悶。

`P` 是相對於 `F` 放大 1.18 倍，不是死板的中央裁切，所以直拍、橫拍、
19.5:9 的手機比例都不會爆框。橫拍素材出 9:16 時兩者都會留模糊邊，`P` 的畫面比較滿。

## 動畫元件與必填參數

`checklist`(title, items) ／ `formula`(title, rows) ／ `stamp`(line1) ／
`bars2`(title, items) ／ `donut`(title) ／ `count`(value) ／ `vs`(left, right)

| 模式 | 60 秒 | 2.5 分鐘 |
|---|---|---|
| 一（雙畫面） | 3–5 個 | 10–15 個 |
| 二（單機位） | **5–7 個** | **15–20 個** |

模式二常用法：`checklist` 放賣點與規格、`vs` 放「用之前／用之後」或「別人／我們」、
`formula` 放售價組成或成本試算、`count` 放數量與天數、`stamp` 放一句結論。
`precheck.py` 會擋缺參數，但別依賴它——寫的時候就查表。

## 模式二專屬：商品／產品片怎麼選段

自錄片沒有「講完一個概念」這種天然邊界，要靠結構模板。60 秒版本挑一個：

| 模板 | 結構 | 適合 |
|---|---|---|
| 痛點→解法 | 痛點 → 為什麼一直沒解決 → 這個東西怎麼解 → 怎麼用 | 功能型商品 |
| 開箱 | 我為什麼買 → 拆開第一印象 → 兩個優點一個缺點 → 適合誰 | 實體選物 |
| 迷思破解 | 大家都以為 X → 其實是 Y → 證據 → 那該怎麼做 | 知識型帶貨 |
| 使用教學 | 常見錯誤 → 正確步驟 1-2-3 → 差別在哪 | 保養、工具、軟體 |
| 見證 | 之前的狀況 → 用了多久 → 具體改變 → 給誰的建議 | 客戶訪談 |

規則：

- **前 3 秒必須是鉤子**，而且鉤子要來自逐字稿裡他真的說過的話，不要另外補錄旁白。
  找不到好鉤子就換段，不要硬做。
- **一支只講一件事。** 開箱片最常見的失敗是把五個賣點塞進 60 秒，結果一個都沒記住。
- **要有一個具體的東西**：一個數字、一個對比、一個看得到的動作。全是形容詞的段落不要用。
- 2–3 分鐘版本 = 60 秒版本 + 使用情境 + 一個缺點 + 適合／不適合誰。
  **主動講缺點的片子留存率明顯比較好**，不要把它剪掉。
- 缺 demo 畫面時，用 `P` 版面 + `checklist` 動畫承接，不要硬插無關的 B-roll。

## 內容安全（每一支都要過）

### 兩種模式共用

真實客戶名、後台畫面（帳號／真實營收數字）、他人姓名、自家報價、
過期資訊（「這週特價」）、密碼與未公開連結、灰色手法、
講者自己說「這個不用講出去」、第三方講師的段落。

### 模式一額外要看：**立場衝突**

內容講給 A 群人聽、但要招的是 B 群人時，段落再精采也不能用——
這是要重新選段，不是重新配字幕。（實例見 `references/手冊.md` 第 8 章。）

### 模式二額外要看：**廣告用語**

自錄商品片最容易出事的不是隱私，是**講過頭**。逐條檢查：

| 類別 | 要找什麼 | 處理 |
|---|---|---|
| 療效／醫療用語 | 治療、根治、消炎、抗菌、抗癌、瘦身、豐胸、生髮、降血糖 | 食品、保養品、一般商品**一律不能用**。改講使用感受 |
| 最高級用語 | 第一、最有效、唯一、絕對、100%、永久 | 拿掉；真的有得獎或第三方數據就標明出處與時間 |
| 沒根據的數字 | 「有效率 90%」「三天見效」 | 沒有可指名的來源就整句剪掉，不要改成模糊講法 |
| 絕對保證 | 保證瘦、無效退費（除非真的有這個政策） | 只留你真的做得到的 |
| 比較性廣告 | 直接指名對手品牌說它爛 | 改成「市面上常見的做法」，不指名 |
| 業配／聯盟 | 廠商送的、有分潤連結、有稿費 | **一定要揭露**，字幕或畫面標「合作」「贈品」 |
| 他人素材 | 網路圖片、對手的影片、他人臉孔入鏡 | 沒授權就不要用 |
| 未上市／未取證 | 還沒拿到許可字號的產品 | 先不要拍 |

> 這張表是實務避雷清單，不是法律意見。牽涉食品、化粧品、醫療器材、保健食品的宣稱，
> 各國規範不同且會變，上架前請自行確認或找專業人士看過。
> **AI 判斷不了「這樣講到底可不可以」，有疑慮就標記起來問使用者，不要自己放行。**

## 交付前

尺寸正確、drift ≤ 0.05 秒、內容段無 > 0.9 秒靜音、字幕全覆蓋且沒切語尾、
片頭圖卡最右白字 ≤ 寬 − 60px、動畫不重疊不超長、每 10–20 秒有畫面變化、
內容安全全過、檔名照 `編號_主題_長度_尺寸.mp4`、
並把「為什麼這樣剪、剪掉了什麼」寫進 `_成品/00_影片清單.md`。
最後那份清單是整套流程能長期跑下去的關鍵——三個月後沒人記得為什麼某段沒用。
